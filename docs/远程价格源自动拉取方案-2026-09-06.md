## 2. 本项目落地设计

### 2.1 价格来源三层化（核心）

`model_price` 表新增 `source` 列，schema v2 → v3：

| 来源 | 含义 | 优先级 |
|---|---|---|
| `manual` | 用户手动新增/改价的规则 | **最高** |
| `remote` | 从远程网址自动拉取（默认 = sub2api 的 URL） | 其次 |
| `builtin` | 内置默认种子（v2 的 20 行自动归入） | 兜底 |

- `v_record_cost` 匹配排序改为：**来源优先级 → 供应商精确 → 生效时间最新**（来源先于供应商：手动通配也压过远程精确，与 sub2api 的 Group 全量覆盖语义一致）
- 时段闭环按来源隔离：manual 改价只关 manual 段、remote 更新只动 remote 段（唯一索引加入 source 维度）
- 语义自洽：历史记录（早于远程首拉时刻）自动回落 builtin；remote 从拉取时刻起接管未手动定价的模型；远程价变动 = 关旧 remote 段 + 开新段

### 2.2 远程拉取器（billing.cjs）

- 配置（config.json，UI 可改即时生效）：
  `billing.remotePricing: { enabled, url, hashUrl, intervalHours }`，url/hashUrl 默认预填 sub2api 的两个地址
- 流程：哈希比对（与 meta 记录相同则跳过，省流量）→ 全量拉取 → `parseLiteLLM` 解析 → **只入库本地真实出现过的模型**（交集，避免塞 3561 行废数据）→ 事务内逐模型：无 remote 段则插入首段、同价跳过、异价关旧段开新段（`effective_from = 拉取时刻`）→ 记哈希/时间/日志
- 失败仅记日志，不阻断数据同步（与 prices.json 同步同一容错模式）
- 触发：定时同步流程内检查（距上次超过 `intervalHours` 且启用）+ 计费规则页「立即拉取」按钮（force 跳过哈希短路）

### 2.3 界面（计费规则页）

- 新增「远程价格源」设置组：启用开关、拉取网址、哈希校验网址、检查间隔、上次拉取状态（时间/模型数）、立即拉取按钮
- 价格表加「来源」列 pill（手动/远程/内置），历史抽屉显示来源
- 现有「从价格源导入」手动确认面板保留，确认写入 = manual 来源

### 2.4 多设备

prices.json 整表同步机制不变（含 source 列）；两台设备拉同一远程源内容天然一致，LWW 整文件覆盖保持简单。

### 已知说明

- **默认源覆盖度**：Wei-Shaw 精简源当前仅 163 条，本次命中本地 7 个模型（gpt-5.6-sol、gpt-5.5、gpt-5.4、deepseek-v4-pro/flash、codex-auto-review、minimax-m2.7，均为 USD 价）。GLM/Kimi/Qwen 等 CNY 模型不在其中，继续由 builtin 内置价兜底；网址随时可在界面改（如换 LiteLLM 官方全量表）。
- **remote 价可能高于内置价**（如 deepseek-v4-pro remote USD 1.32/3.96 ≈ ¥9.5/28.5，builtin 为 ¥2/8）：这是「远程 > 内置」优先级的直接结果。如需沿用内置价，对该模型手动改价一次（manual 永远最高）或关闭自动拉取。
- 哈希短路：远程无变化时只拉哈希文件；「立即拉取」按钮强制跳过短路。
