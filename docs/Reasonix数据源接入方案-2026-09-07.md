# Reasonix 数据源接入方案（token 消耗统计 + 计费统计）

> 日期：2026-09-07 ｜ 状态：已实施
> 结论先行：**可行**，以「每日账本型适配器」接入（与 WorkBuddy 同为文件扫描型），对现有统计/计费链路 **零结构性改动**。
> 关键发现：Reasonix 的 token 是**互斥桶**口径（cache_miss / cache_hit 分离），而本项目是**包含式**口径（inputTokens 含 cacheRead）。二者可通过一次无损映射对齐，`v_record_cost` 计费视图**无需修改**。

### 1.2 统计维度

一条 `UsageRecord` 的维度字段（ZCode `model_usage` 行 → 归一化）：

| 维度 | 字段 | ZCode 来源 |
|---|---|---|
| 软件源 | `source` | 常量 `"zcode"`（全链路按源隔离，顶部切换联动所有视图） |
| 设备 | `deviceId` / `deviceName` | 工具级 device_id；源级 `~/.zcode/v2/telemetry-state.json` 的 `deviceMid` |
| 供应商 | `providerId` | `provider_id` 为裸 UUID → `PROVIDER_MAP` 未命中 → `providerByModel()` 按模型名前缀推断（实测 `deepseek-v4-pro-0813` → `DeepSeek`） |
| 模型 | `modelId` | `normalizeModel()`：去路径/冒号、下划线转连字符、剥日期快照后缀（`-0813` 命中 `\d{4}$`）→ `deepseek-v4-pro` |
| 会话/智能体/模式 | `sessionId` / `agent` / `mode` / `taskType` | `session_id` / `agent` / `mode` / `task_type` |
| 状态 | `status` | `status`（success / error / cancelled） |
| 时长 | `durationMs` / `completedAt` | `duration_ms` / `completed_at` |

**5 个 token 桶**：`inputTokens` / `outputTokens` / `reasoningTokens` / `cacheCreationTokens` / `cacheReadTokens`。

### 1.3 计算方式

- **增量抽取**：`SELECT ... WHERE started_at > ? ORDER BY started_at`（L127-130）；`since = anchor - 24h`（`sync.cjs` L161）；锚点单调不回退（L168-170）。
- **总量口径**（`extraExpr()` L341）：
  - `full`（完整口径）= `input + output + reasoning`
  - `compact`（简洁口径）= `input + output`
- **缓存命中率**（`getSummary` L607）：`cache_read / input`。**注意 `input` 已包含 `cache_read`**（OpenAI 语义，ZCode/Codex/WorkBuddy 三源实测一致），故恒 ≤ 100%。
- **幂等**：记录 id = `${deviceId}:zcode:${源记录id}`，`INSERT OR REPLACE`（`db.cjs` L202-208）。
- **计费**（`v_record_cost` L104-124）：
  ```
  费用 = (净输入 × input价 + cacheRead × 读价 + cacheCreation × 写价 + (output + reasoning) × output价) / 1e6
  其中 净输入 = inputTokens − cacheReadTokens
  ```
  价格匹配优先级：来源（`manual` 手动 > `remote` 远程 > `builtin` 内置种子）→ 供应商精确匹配 → `effective_from` 最新。
  币种换算在 JS 层 `toDisplay()`（L313），改汇率后全部历史费用即时重算。
- **多机同步**：日分片 `usage-tracker/data/<deviceId>/<YYYY-MM-DD>.jsonl.gz`，内容 SHA1 记账增量传输；`source` 随记录上云，跨设备合并后仍按源隔离。

## 二、Reasonix 本地数据勘察

### 2.1 权威数据源（采用 ✅）

**`<state root>/stats/YYYY-MM-DD.jsonl`** —— 每日账本，逐次请求聚合。

- **State Root 解析优先级**（与 ccstats 一致）：`REASONIX_STATE_HOME` → `REASONIX_HOME` → 平台默认（Windows `%APPDATA%\reasonix`，macOS/Linux `~/.reasonix`）。
- 仅文件名为合法日期（`YYYY-MM-DD.jsonl`）的账本会被扫描。

**字段**（ccstats `authoritative-token-accounting` 逆向 + Reasonix v1.19.5「全产品用量统计」发布说明）：

| 字段 | 含义 |
|---|---|
| `cache_miss` | 未命中缓存的**普通输入**（显式正数时为权威值） |
| `prompt` | 总 prompt token；`cache_miss` 缺失时用于回退：`input = prompt − cache_hit` |
| `cache_hit` | 缓存命中读数 |
| `completion` | 总完成 token（**包含** reasoning） |
| `reasoning` | 推理 token（`completion` 的**子集**） |
| `requests` | 请求次数（>0 时作为调用计数，否则记 1） |
| `total` | 供应商自报总量，仅用于判断记录是否含用量 |
| `turn` | 轮次标记；`turn=true` **不是**一次 provider call，须跳过 |
| `cost_complete` / `valuation_usd` | 客户端估值（非账单） |

**关键约束**：该账本**没有**持久化 cache write，故 `cache_creation` 恒为 0；也**没有**可验证的 session/project 归属。

### 2.2 不采用的候选

| 位置 | 结论 |
|---|---|
| `usage-catalog/v1.sqlite` | **可重建投影**（`reasonix catalogs reindex usage` 可重建），非权威，官方明示「Daily statistics JSONL remains authoritative」 |
| `~/.reasonix/usage.jsonl` | 旧版每轮摘要（tokens + cost + cache hit），**与 stats 账本内容重叠**，同时读取会重复计数 → 一期不接入 |
| `sessions/**/*.jsonl` 会话转录 | 逐条 message 解析，与 WorkBuddy 同模式但字段不同（role/content/tool_calls）；账本已覆盖 → 不采用 |
| `config.toml` 的 `default_model` | 仅作**模型名兜底**（记录缺 model 字段时），不参与计量 |

### 2.3 本机现状

`~/.reasonix/` 仅存在 `locks/` 目录，**无 `stats/`**——即 Reasonix 未在本机产生用量。适配器须优雅降级（检测到目录但无账本 → `validate()` 返回 false，同步日志提示"未检测到"）。

## 三、口径冲突与映射（本次接入的核心）

Reasonix 的 `cache_miss` / `cache_hit` 是**互斥桶**（相加才是总输入），而本项目 `inputTokens` 是**包含式**（含 `cacheReadTokens`）。直接照搬会导致输入被**重复扣除**一次缓存、费用被低估。

**无损映射方案**：

```
inputTokens          = prompt  (= cache_miss + cache_hit)
cacheReadTokens      = cache_hit
outputTokens         = completion − reasoning
reasoningTokens      = reasoning
cacheCreationTokens  = 0        （账本无此数据）
```

代入 `v_record_cost` 验算：

```
净输入 = inputTokens − cacheReadTokens = (cache_miss + cache_hit) − cache_hit = cache_miss  ✅ 正是应计费的普通输入
(output + reasoning) = (completion − reasoning) + reasoning = completion                    ✅ 正是应计费的总输出
费用 = cache_miss × input价 + cache_hit × 读价 + 0 × 写价 + completion × output价            ✅ 与 Reasonix 自身估值口径一致
缓存命中率 = cacheReadTokens / inputTokens = cache_hit / prompt                              ✅ 与项目现有"input 含缓存"口径一致
```

**结论：映射后 `v_record_cost` 公式无需任何改动**，缓存命中率、总量口径、四维费用榜、明细费用列全部自动正确。

## 四、可行性结论与影响评估

| 影响面 | 评估 |
|---|---|
| 聚合查询（`db.cjs`） | **零改动**。所有查询按 `source` 参数过滤/分组，新源自动纳入总览/趋势/热力/四维榜/明细 |
| 计费（`v_record_cost` / `model_price`） | **零改动**。见第三节验算；`deepseek-v4-flash` / `deepseek-v4-pro` 已有内置价，开箱即出费用 |
| 同步引擎（`sync.cjs`） | **零改动**。抽取循环由注册表驱动；日分片按 `source` 自然隔离 |
| 设备标识 | **零风险**。Reasonix 无稳定设备文件 → `getDeviceId()` 返回 `null`，走既有回退链（zcode `deviceMid` → UUID），与其他源共用同一设备单元 |
| 前端 | 仅扩展类型注释 / mock / 默认配置；数据源清单由 `list_sources` 下发，UI 自动出现新源 |
| 风险 | 低。单源失败自动跳过（`sync.cjs` L173 已有 try/catch）；账本按日切分，增量只扫相关日期文件 |

## 五、统计指标定义（Reasonix → UsageRecord 映射）

| UsageRecord 字段 | 取值 | 说明 |
|---|---|---|
| `id` | `${deviceId}:reasonix:${YYYY-MM-DD}:${行号}` | 幂等去重键；账本为 append-only 日文件，行号稳定（与 ccstats「line hash 幂等」同语义） |
| `source` | `"reasonix"` | |
| `deviceId` / `deviceName` | 工具本机 device_id / 用户设备名 | |
| `providerId` | `providerByModel(modelId)`，兜底 `"DeepSeek"` | Reasonix 为 DeepSeek 原生；仍复用 ZCode 的模型名前缀推断 |
| `modelId` | `normalizeModel(model)` | 与价格表口径一致；缺失时回退 `config.toml` 的 `default_model`，再缺记 `unknown` |
| `variant` | 记录 `effort` / `reasoningEffort`（若有） | 推理档位 low/medium/high/max |
| `sessionId` / `taskType` | 记录 `sessionId` / 会话性质（若有） | 账本无可靠归属，有则取、无则留空 |
| `inputTokens` | `prompt`（缺则 `cache_miss + cache_hit`） | **含缓存**，与项目口径一致 |
| `outputTokens` | `completion − reasoning` | 可见输出（剔除推理） |
| `reasoningTokens` | `reasoning` | |
| `cacheReadTokens` | `cache_hit` | |
| `cacheCreationTokens` | `0` | 账本不持久化缓存写入 |
| `startedAt` | 记录时间戳；缺失回退账本日期（本地 12:00） | 保证按日归档正确 |
| `status` | 记录 `status`，缺省 `"success"` | |

**数据质量边界**（不静默钳制为零，跳过并记日志）：负数 token、`reasoning > completion`、`cache_hit > prompt`、`turn === true` 的轮次行、JSON 损坏行。

**计费指标**：完全复用现有体系——总费用 / 今日 / 本月 / 较上月同期、四维费用榜、每日费用趋势、未配置价格模型提醒；**不使用** Reasonix 自报的 `valuation_usd`（客户端估值且非账单），统一由本地价格表重算，保证跨源可比。

## 六、数据流转

```
<state root>/stats/YYYY-MM-DD.jsonl            （只读：token 桶 / model / 时间戳，不读任何对话内容）
   │  REASONIX_STATE_HOME → REASONIX_HOME → %APPDATA%\reasonix | ~/.reasonix
   ▼
adapter-reasonix.extract：按日期过滤文件 → 逐行解析 → turn 行跳过 → 互斥桶归一化 → 行号去重
   ▼
UsageRecord[]（id = deviceId:reasonix:日期:行号）
   │  sync.cjs 抽取阶段（checkpoint 锚点 + 24h 回扫，单源失败跳过）
   ▼
本地 SQLite usage_record（幂等 INSERT OR REPLACE）
   ├─► v_record_cost 计费视图 ─► KPI / 趋势 / 四维费用榜 / 明细费用列
   ├─► 聚合查询 ─► 总览 / 设备 / 趋势 / 热力图（source=reasonix 自动隔离）
   └─► WebDAV 日分片上传 / 拉取 / 合并（无需改动，多机自动汇总）
```

## 八、遗留与后续

- **模型名兜底风险**：账本若长期缺 `model` 字段，会集中落到 `config.toml` 的 `default_model`，造成模型维度失真。待实机数据确认后收敛。
- **`usage.jsonl` 兜底**：旧版 Reasonix（无 `stats/`）暂不支持。待确认其字段与 `stats/` 无重叠后再决定是否接入。
- **会话/项目维度**：账本无归属，一期不伪造（与 ccstats 决策一致）。
