# 计费功能落地方案（2026-09-05）

> 状态：**已实施（2026-09-06）**。原型验证与实施后实测记录见 §10，界面以 §8 两页设计稿为准并已落地。
> 实施说明：费用榜按费用降序、effectiveFrom=0 显示为「全部历史」、导入面板实时拉取 LiteLLM 实测可用（收录 deepseek-v4-pro/gpt-5.6-sol 等）。

---

## 1. 目标与结论摘要

给 Dosage Sync 增加**个人模型消费核算**能力：

- 每条用量记录按「模型单价 × token 分解」算出费用，历史记录**始终按消费当时生效的价格**计算；
- 价格**随时可改**，改价自动生成新价格版本（旧版本保留），全部历史费用立即重算；
- 价格可**手动维护**，也可从 **LiteLLM / OpenRouter** 两个公开价格源一键导入（国内厂商价格无公开 API，手动填）；
- 多设备通过 WebDAV 同步一份共享价格表，保证各机器算出的费用口径一致；
- 界面上：侧栏新增「**费用**」（纯展示）与「**计费规则**」（价格管理）两个页面，明细页加费用列；已出 HTML 设计稿（§8）。

**一句话结论**：采用「**查询时动态计算**」——价格存独立的时段版本表，查询时 JOIN 计算，token 记录本身零改动、同步协议零改动。已验证 12k 条全表聚合仅 11ms，性能无压力。

---

## 2. 方案选型

三个候选方案对比：

| | A. 查询时动态计算（**推荐**） | B. 入库时预算 cost 列 | C. 接外部计费平台 |
|---|---|---|---|
| 价格动态调整 | ✅ 改价即全历史重算 | ❌ 需全表重算 | — |
| 历史按当时价 | ✅ 时段版本天然支持 | 需额外存 price_id | — |
| usage_record 侵入 | 无（新增独立表） | 加列，**同步分片格式变更** | — |
| 查询性能 | ✅ 12k 条 11ms（已实测） | 最快 | — |
| 复杂度 | 低（一张表 + 一个视图） | 中（迁移 + 协议兼容） | 高（外部依赖重） |

方案 C（OpenMeter / Lago 等）面向 SaaS 对客计费，个人工具用它属于过度设计；方案 B 唯一优势在千万级记录性能，本工具量级（万级）用不上。**选 A**。

**核心设计红利**：费用是派生数据，不落盘、不进 WebDAV 日分片 → 现有同步协议（日分片 + manifest + 内容 hash）**完全不动**，旧版客户端无缝共存。

## 3. 数据模型

### 3.1 价格表（新增，进 SCHEMA_VERSION 1→2 迁移）

```sql
CREATE TABLE model_price (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  provider_id TEXT,              -- NULL = 不限供应商（通配）；填值则仅匹配该供应商
  model_id   TEXT NOT NULL,      -- 精确匹配 usage_record.model_id
  input_per_m      REAL NOT NULL DEFAULT 0,  -- 元（或分）/$ per 百万 token
  output_per_m     REAL NOT NULL DEFAULT 0,
  cache_read_per_m REAL NOT NULL DEFAULT 0,  -- 缓存命中单价（国内厂商通常 0.1~0.2 倍输入价）
  cache_write_per_m REAL NOT NULL DEFAULT 0, -- 缓存写入单价（Anthropic 系才有，其余 0）
  currency TEXT NOT NULL DEFAULT 'CNY',      -- 该行单价的币种
  effective_from INTEGER NOT NULL,           -- epoch ms（含），生效起
  effective_to   INTEGER,                    -- epoch ms（不含）；NULL = 至今
  updated_at INTEGER NOT NULL,
  updated_by TEXT                            -- 改价的设备名（多设备可追溯）
);
-- 查询索引 + 防重叠时段兜底（provider NULL 用 COALESCE 归一后才能进唯一索引）
CREATE INDEX idx_price_lookup ON model_price(model_id, effective_from);
CREATE UNIQUE INDEX idx_price_period ON model_price(COALESCE(provider_id,''), model_id, effective_from);
```

### 3.2 成本视图（核心）

```sql
CREATE VIEW v_record_cost AS
SELECT r.*,
  ( COALESCE(mp.input_per_m,0)      * (r.input_tokens - r.cache_read_tokens)   -- 净输入（README 实测口径：input 含 cacheRead）
  + COALESCE(mp.cache_read_per_m,0) *  r.cache_read_tokens                    -- 缓存命中单独计价
  + COALESCE(mp.cache_write_per_m,0)*  r.cache_creation_tokens                 -- 缓存写入
  + COALESCE(mp.output_per_m,0)     * (r.output_tokens + r.reasoning_tokens)  -- 推理跟随输出价
  ) / 1000000.0                                   AS cost_native,             -- 按该行币种的原生成本
  mp.currency                                     AS cost_currency,
  mp.id                                           AS price_id
FROM usage_record r
LEFT JOIN model_price mp ON mp.id = (
  SELECT p.id FROM model_price p
  WHERE p.model_id = r.model_id
    AND (p.provider_id IS NULL OR p.provider_id = r.provider_id)
    AND p.effective_from <= r.started_at
    AND (p.effective_to IS NULL OR p.effective_to > r.started_at)
  ORDER BY (p.provider_id IS NOT NULL) DESC, p.effective_from DESC  -- 供应商精确 > 通配；同时段取最新版
  LIMIT 1);
```

匹配优先级：`供应商精确` → `仅模型通配` → 无匹配（cost_currency 为 NULL，费用按 0 并打「未配置」标记）。**不引入 source 维度**：实测同一模型跨源供应商一致（如 gpt-5.6-sol 在 zcode/codex 都是 OpenAI），引入只会让配置翻倍（YAGNI）。

### 3.3 币种换算（在 JS 层做，不进 SQL）

- 汇率是用户可改的配置（`billing.usdToCny`，默认 7.2），改了要**即时生效**，所以 SQL 只产出 `cost_native + cost_currency`，换算聚合在 JS：`SUM(各币种 native) → ×汇率 → 相加`。
- 已知取舍：历史记录统一按**当前汇率**换算，不追溯历史汇率。个人核算可接受，方案不引入汇率历史表。

## 4. 价格从哪来（数据源）

| 来源 | 覆盖 | 字段 | 接入方式 | 可靠性 |
|---|---|---|---|---|
| **手动填写** | 全部 | 四项单价 + 币种 + 生效日期 | 计费页表格 | ★★★ 主路径 |
| **从用量一键生成草稿** | 本库出现过的全部 (供应商， 模型) | 预填行，逐个填价 | 扫描 `v_record_cost` 中未配置且有 token 的模型（原型实测 7 个，其中 1 个是 Antigravity 配额记录，实施时该源整体排除计费后剩 6 个：dots3-note-prev、gpt-5.4、minimax-m3/m2.7、codex-auto-review、qwen3.7-max-preview） | ★★★ |
| **LiteLLM 价格表** | 3561 模型（OpenAI/Anthropic/Google/DeepSeek/Qwen…） | `input/output/cache_read/cache_creation_cost_per_token`（USD/token） | 定期更新 JSON：`raw.githubusercontent.com/BerriAI/litellm` 主源 + `cdn.jsdelivr.net` 镜像自动回退 | ★★（2026 新模型命名未必收录，导入报告命中/未命中清单） |
| **OpenRouter API** | 431 模型，实时 | `pricing.prompt/completion/input_cache_read`（USD/token 字符串） | `GET /api/v1/models`，按 `vendor/` 后缀匹配本地 model_id | ★★ |

导入为「预览 → 确认」两步：列出新增/改价 diff，用户确认后才写库；导入价格生效日期默认今天，可改。网络请求支持可选代理设置（`billing.importProxy`，默认空=直连；jsdelivr 镜像国内通常可直连）。

## 5. 动态调价机制

改价 = 事务内「**关闭现行价格段 + 插入新价格段**」：

```
glm-5.3 @智谱GLM   输入4 输出16 缓存0.8   [2026-06-01  ..  2026-08-15)   ← 旧版本永久保留
glm-5.3 @智谱GLM   输入2 输出8  缓存0.4   [2026-08-15  ..  ∞)            ← 改价新版本
```

- 改价时可指定**生效日期**（默认今天）：既支持"从现在起调价"，也支持"补录历史价"（例如发现 6 月时其实是 4 元，就把生效日设为 6 月 1 日修正过去）；
- 全部历史费用立即按新版本重算（查询时动态计算的直接收益）；
- 提供「查看该模型价格版本历史」和「删除该模型全部版本」（配错导入时清重来，无空档问题）；
- 单版本级删除不提供（语义复杂易出错，重改一次即可达成同样效果）。

## 6. 多设备价格一致性

价格表属于**共享数据**（不是设备配置），走 WebDAV 一份共享文件：

- 文件：`usage-tracker/prices.json`：`{ updatedAt, updatedBy, prices: [...全部版本行] }`（几 KB 量级）；
- 时机：每次同步引擎的抽取阶段完成后顺带处理——远端文件 `updatedAt` 更新则整表替换本地（事务内 DELETE+INSERT，写一条同步日志），本地更新则上传，`meta` 表记内容 hash 防重复 PUT；
- 冲突策略：**LWW 整文件覆盖**（改价是低频操作，被覆盖方在同步日志中可见"价格表被设备 X 覆盖"）。不引入逐行合并——复杂度与收益不成比例；
- 关闭计费开关不影响价格表同步（价格表是数据，开关只是 UI 显示偏好）。

## 7. 计费口径（边界逐条定死）

| 项 | 口径 | 依据 |
|---|---|---|
| 净输入 | `(input - cacheRead) × 输入价` | README 实测：input **含** cacheRead（三源口径已归一） |
| 缓存命中 | `cacheRead × 缓存读价` | 国内厂商缓存价约为输入价 0.1~0.2 倍 |
| 缓存写入 | `cacheWrite × 缓存写价` | 仅 Anthropic 系收费，其余填 0 |
| 推理 | `(output + reasoning) × 输出价` | 业界通行：reasoning 按输出计价，不设单独价字段 |
| 失败/取消记录 | **照常计费**（有 token 就算钱） | token 是实际消耗；0 token 的失败记录天然为 0。不做开关（KISS） |
| Antigravity 系 | **排除计费**（其数值是配额百分比点，非 token） | 该两源当前已隐藏；未来恢复时在成本查询中按 source 排除并注明 |
| 未配置价格的模型 | 费用计 0 + 明确打「未配置」标记（明细列显示 `—`，计费页有未配置清单） | 错误的默认价比没有更误导 |
| 总量口径开关（full/compact） | 不影响费用（费用有自己的完整公式） | — |
| 精度 | REAL 浮点，元为单位；明细显示 4 位小数，聚合 2 位 | 12k 条累计误差 << 分 |

## 8. 界面设计（加在哪里）—— 两页方案

> **2026-09-06 修订**：应用户要求由单一「计费」页拆为两个独立页面，并已产出 HTML 设计稿（设计完全复用现有设计系统，token / 卡片 / 表格 / 开关 / pill 与 `src/styles/global.css` 一致，默认浅色、可切深色）：
> - **[docs/设计图-费用页.html](设计图-费用页.html)** —— 费用展示页全貌（KPI、趋势图、三维度费用榜、未配置提醒横幅）
> - **[docs/设计图-计费规则页.html](设计图-计费规则页.html)** —— 计费规则页全貌（设置组、15 行价格表、未配置行高亮，底部含**改价弹层 / 版本历史 / 导入预览**三个关键交互状态示意）

### 8.1 侧栏导航 4 项 → 6 项

`总览 / 用量明细 / 费用 / 计费规则 / 同步日志 / 设置`。「费用」「计费规则」插在用量明细之后；`App.vue` 沿用现有 v-show 模式挂 `CostsView` 与 `BillingRulesView` 两个视图。

**拆分理由**：原单页要容纳全局设置 + 价格管理 + 改价/历史 + 导入 + 草稿 + 费用榜六块内容，滚动过重；拆开后「费用」是纯读路径（展示），「计费规则」是纯写路径（配置），职责清晰且费用信息有了集中展示地。

### 8.2 「费用」页（纯展示）

自上而下（与设计稿一致）：

1. **未配置提醒横幅**：`minimax-m3 与 gpt-5.4 尚未配置价格，相关记录暂未计入费用（约 ¥12.08）` + 「去计费规则补齐」按钮；
2. **KPI 4 卡**：本月费用（副行较上月同期）、今日费用（副行调用次数）、累计费用（副行 USD 折算说明）、未计入费用（warn 橙色，副行未配置模型数与记录数）；
3. **费用趋势卡**：SVG 面积图，近 7 / 30 / 90 天 tab 切换，悬停查看单日金额，末尾今日虚线；
4. **费用榜卡**：按模型 / 供应商 / 设备三个 tab；列：排名、名称、供应商（币种）、调用、Token、费用、占比条；未配置模型的费用列显示「未配置价格」pill；
5. **口径脚注卡**：计费公式 + Antigravity 排除 + 失败记录照常计费 + 汇率即时生效说明。

数据通道：完全复用现有 `getSummary / getTrend / getAggregate` 扩展（跟随顶栏数据源切换与设备筛选，与总览页行为一致）。

### 8.3 「计费规则」页（配置与写入）

1. **计费设置组**：启用费用统计开关（默认关）、显示币种（CNY/USD）、USD→CNY 汇率输入、导入代理（可选，留空直连；jsdelivr 镜像无代理也可直连）；汇率修改后全部历史费用即时重算；
2. **模型价格表**：列 = 模型 / 供应商 / 输入 /M / 输出 /M / 缓存读 /M / 缓存写 /M / 币种 / 现行版本（如 `08-15 起 · 1 个历史版本`）/ 操作（改价 · 历史 · 删除）；**未配置行橙色底高亮** + 「未配置 · N 条记录」pill + 「去配置」按钮；表头右侧「从价格源导入」「从用量生成草稿」两个入口；
3. **三个关键交互**（实现为浮层/抽屉，设计稿页面内以缩略形式呈现）：
   - **改价弹层**：四项单价 + 币种 + 生效日期（默认今天，可改到过去补录历史价），说明文案点明"关闭现行段生成新版本，历史费用自动重算"；
   - **价格版本历史抽屉**：时间线展示各版本段（现行高亮蓝点），说明删除语义；
   - **导入预览面板**：LiteLLM / OpenRouter 源切换，逐行 `新增 / 变更 / 未收录` 三态 + 变更 diff（`4.00/16.00 → 2.00/8.00`），勾选确认写入，生效日期统一指定。

### 8.5 计费总开关

`billing.enabled` **默认关闭**。关闭时：侧栏「费用」项隐藏（导航回到 5 项），明细页费用列、设备卡费用行、导出费用列均不渲染；「计费规则」页始终可达（否则无法开启），后端字段照常返回（join 成本 11ms，不值得为关做查询分支）。

## 12. 风险与限制

- **导入覆盖度**：2026 年的新模型（glm-5.3、gpt-5.6-sol 等）在 LiteLLM/OpenRouter 的收录有滞后，自动导入命中不了属预期，主路径是手动 + 草稿生成；
- **LWW 覆盖**：两台设备同时改价，后同步者覆盖前者（日志可见）；
- **性能边界**：视图相关子查询在 10 万条记录量级约 100ms，个人数据量级（万级）无感；若未来十万条级出现明显变慢，届时再引入 cost 缓存列（增量维护），本期不做；
- **口径依赖**：公式依赖「input 含 cacheRead」这一已实测口径，适配器层若变更口径需同步检查成本公式（在 db.cjs 视图处有注释锚点）。
